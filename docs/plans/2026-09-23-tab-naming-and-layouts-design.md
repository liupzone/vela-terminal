# Vela：标签页命名与分屏布局保存

日期：2026-09-23

## 1. 目标

**标签页命名**：给标签页起一个固定名字，之后 shell 改标题也不影响；清空则恢复跟随。

**分屏布局保存**：把当前的分屏结构存下来，之后可以原样恢复。两种用法：

- **命名布局**：存成有名字的布局，从菜单或命令面板随时恢复
- **会话恢复**：关掉 Vela 再打开时，自动恢复上次的标签页与分屏

保存内容：分屏树结构（方向、分隔比例）、每个分屏的类型（终端 / 系统性能 / 文件面板）、
每个终端的启动目录、标签页名称。

**不保存终端的历史输出**（回滚缓冲动辄数 MB，会让文件膨胀且恢复变慢）。恢复出来的是
干净的 shell，工作目录与原布局一致。

## 2. 关键设计

**布局是一份纯数据。** `vela/layout.py` 负责树 <-> 字典的互转，不依赖 GTK，因此可以
对序列化/反序列化、版本兼容、损坏数据做完整单元测试。数据长这样：

```toml
[[layouts.items]]
name = "开发"
title = "dev"
tree = { type = "split", orientation = "h", position = 540,
         first = { type = "terminal", cwd = "/home/me/project" },
         second = { type = "sysinfo" } }
```

**恢复时要容错。** 布局可能引用已删除的目录、未知的分屏类型、或来自更新版本。恢复时：
目录不存在就回退到主目录并提示；未知类型降级为终端；结构损坏就跳过这个布局而不是崩。
数据带 `version` 字段，便于以后迁移。

**会话与命名布局共用一套格式**，只是存放位置不同：会话存在 `~/.local/state/vela/session.json`
（状态类数据），命名布局存在配置的 `[layouts]` 段（用户资产，值得进配置文件和备份）。

**会话恢复默认关闭。** 自动恢复会让「打开终端」变成「打开上次的一堆东西」，不是所有人
都想要，所以做成可配置（`behavior.restore_session`，默认 false），并在首次开启时说明。

## 3. 改动清单

```
vela/layout.py     新增：树 <-> 字典、版本、容错、命名布局读写
vela/tab.py        命名：set_title_override / clear_title_override
vela/window.py     标签重命名入口（双击/右键/快捷键）、布局动作、会话保存与恢复
vela/prefs.py      会话恢复开关、布局列表管理
vela/config.py     [layouts] 段与 behavior.restore_session
```

## 4. 测试与验收

- `tests/test_layout.py`：树序列化往返、嵌套结构、每种分屏类型、比例保留、未知类型降级、
  损坏数据、版本字段、缺失目录、命名布局的增删改查、重名覆盖。
- `tests/test_tab_naming.py`：命名后不跟随 shell 标题、清空后恢复跟随、重名与空名处理。
- `tools/ui_smoke.py`：真实窗口里重命名标签、保存布局、改乱布局后恢复、验证分屏结构与
  类型一致；会话保存后重新读取一致。

## 5. 明确不做（YAGNI）

- 保存终端历史输出、滚动位置、正在运行的程序（需要 PTY 代理，另一件事）
- 布局的图形编辑器、导入导出到文件、跨机器同步
- 每个布局独立的主题与字体（属于窗口级设置）
