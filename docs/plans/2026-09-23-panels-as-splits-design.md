# Vela：面板作为分屏（系统性能 / 文件面板可再分屏）

日期：2026-09-23

## 1. 目标

现在侧栏是终端区之外的一块固定宽度区域，内部只能上下两格。改为：**系统性能面板和
文件面板就是普通分屏**，和终端共用同一套分屏树，因此可以任意分屏、任意嵌套、任意
拖动比例。

结果：一个标签页里可以有

```
终端 | 系统性能            （左右并排）
终端 / 文件面板            （上下堆叠）
终端 | 文件面板 / 系统性能  （嵌套）
终端 | 终端 | 文件面板      （三列，其中一列是面板）
```

## 2. 关键设计

**分屏树不区分类型。** `Leaf` 已经只要求 `view` 是一个带 `set_focused()` 的控件，
`_widget_for()` 也已经同时接受 `Gtk.Widget` 和带 `.widget` 的对象。所以树的逻辑不用
改，只要：

1. 让 `SysinfoPanel` / `FileBrowserPanel` 提供和 `TerminalView` 相同的接口
   （`set_focused()`、`apply_theme()`、`title`）。
2. `PaneContainer.split()` 接受 `kind`，按类型创建新分屏的视图。
3. `Tab` 区分「终端分屏」和「面板分屏」：标题、跟随目录、子进程、退出处理只作用于
   终端分屏。

**终端专属操作要有明确的落点。** 复制、粘贴、搜索、清屏、输入等都是终端操作。当前
活动分屏是面板时，这些动作要么作用到该标签页里最近的终端分屏，要么明确提示不可用。
选择「回退到最近的终端分屏」，因为用户按 `Ctrl+Shift+C` 时意图是复制终端内容，而不是
被告知「当前是文件面板」。

**切换而不是替换。** 提供「把当前分屏切换为终端 / 系统性能 / 文件面板」的动作，
这样用户不必先关掉再新建。切换时保留分屏在树里的位置和比例。

**侧栏保留为兼容路径。** `sysinfo.enabled` / `filebrowser.enabled` 继续有效，但含义
变为「启动时在侧栏显示」；新的推荐用法是把它们作为分屏。这样老配置不会失效。

## 3. 改动清单

```
vela/panels.py        新增：面板接口约定 + 把面板包成可分屏视图
vela/pane.py          split() 支持 kind；Leaf 记录 kind
vela/tab.py           区分终端分屏与面板分屏；标题/目录/退出只认终端
vela/window.py        动作：分屏为性能面板 / 文件面板、切换当前分屏类型
vela/prefs.py         说明两种用法
```

## 4. 测试与验收

- `tests/test_panel_splits.py`：树里混合终端与面板时的分屏/关闭/聚焦/最大化；
  终端专属动作在面板为活动分屏时回退到最近终端；切换分屏类型保留位置。
- `tools/ui_smoke.py`：真实窗口里把分屏切成性能面板、再切成文件面板、再切回终端；
  面板分屏参与方向键跳转；关闭面板分屏后其余分屏仍可用。

## 5. 明确不做（YAGNI）

- 把面板拖到另一个窗口、面板独立成标签页
- 面板内部再嵌套终端（面板内容固定）
- 侧栏与分屏两套模式同时显示同一个面板实例（一个面板实例只在一个位置）
