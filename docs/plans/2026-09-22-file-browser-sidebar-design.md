# Vela：文件浏览侧栏

日期：2026-09-22
依赖：Vela Terminal（GTK 3.24 + Gio，均为系统自带）

## 1. 目标

在终端窗口里内置一个文件浏览侧栏，形态对齐成熟文件管理器：

- 顶部面包屑显示当前路径，点击任一段可跳到该层
- 列表三列：**名称 / 权限 / 修改时间**，权限用 `drwxr-xr-x` 符号形式
- 首行 `..` 返回上级
- 文件夹与文件带图标（按 MIME 类型取系统图标）
- 双击进入目录，双击文件用 Vela 既有能力打开（文本/图片内置查看器，其余交系统默认程序）
- 默认**跟随终端当前目录**：`cd` 到哪跟到哪；用户一旦自己导航就停止跟随，可手动恢复
- 显示隐藏文件（点文件），顶部有开关

## 2. 为什么这样做

**侧栏改成多面板容器。** 现在侧栏只放得下 `SysinfoPanel` 一个控件。文件面板要
和系统性能面板并存，所以侧栏从「单一子控件」改成「标签页容器 + 按需挂载的页面」，
每个页面独立开关、独立记住可见性。这比塞两个并排控件更接近截图里的 `files / web /
sysinfo / process` 标签形态，也为后续加更多面板留了位置。

**复用 `files.py` 而不是另写一套。** 打开文件的分发规则（文本/图片内置、目录交文件
管理器、其余交系统默认程序）已经存在且有测试覆盖，文件面板只需要调用它。

**用 GtkTreeView 而不是 GtkListBox。** 三列对齐、可排序、行数多时滚动性能都更好，
且无需自己处理列宽。图标通过 `Gtk.IconTheme` 按内容类型查询，拿到的是用户当前图标
主题里的真实图标。

## 3. 架构

```
vela/filebrowser.py   FileBrowserPanel（Gtk.TreeView + 面包屑 + 工具栏）
vela/fsmodel.py       纯逻辑：目录读取、排序、权限/时间格式化、路径导航
vela/window.py        侧栏改多面板容器；终端目录变化 → 面板跟随
vela/config.py        [filebrowser] 配置节
vela/style.py         侧栏与列表样式
```

数据流：终端 `directory-changed` → 窗口判断面板是否处于跟随状态 → 面板 `set_directory()`
→ `fsmodel.read_directory()` 返回条目列表 → 填入 `Gtk.ListStore`。

## 4. 关键设计

- **纯逻辑与 UI 分离**：目录读取、排序、权限字符串、时间格式化都放在 `fsmodel.py`
  的纯函数里，测试可以直接喂临时目录，不需要显示器。
- **排序**：目录永远排在文件前面，同组内按名称自然序（大小写不敏感），与主流文件
  管理器一致。
- **跟随状态**：`following` 标志。终端目录变化时只在 `following` 为真时跳转；用户
  双击进入某目录或点面包屑会置为假。工具栏有「跟随终端」开关。
- **错误处理**：无权限、目录已删除、路径不存在都在列表区显示一条说明而不是崩溃；
  权限不足的条目照常列出但标注，双击时给出状态栏提示。
- **大目录**：条目上限可配置（默认 5000），超过时截断并提示，避免卡住界面。
- **符号链接**：显示链接目标，目录链接可进入（跟随解析结果）。

## 5. 测试与验收

- `tests/test_fsmodel.py`：临时目录树上的读取、排序（目录优先/自然序）、隐藏文件
  过滤、权限字符串（含 setuid/sticky 位）、时间格式化、上级路径、边界（不存在、
  非目录、空目录、无权限、超大目录截断）。
- `tools/ui_smoke.py` 扩展：面板打开后列出真实临时目录内容、断言三列有值、进入子
  目录、`..` 返回、切换隐藏文件、跟随终端 `cd`、双击文件打开内置查看器。
- 真机验收：与截图一致的列与图标；在终端 `cd` 后侧栏同步。

## 6. 明确不做（YAGNI）

- 文件复制/移动/删除/重命名（危险操作，需要确认流程，另开一轮）
- 多选与拖放、标签页式文件浏览、搜索框（终端已有搜索）
- 缩略图预览、压缩包内浏览、远程挂载
