# Vela：左键切换分屏 + 终端右键菜单

日期：2026-09-22

## 1. 问题

**左键点分屏不切换焦点。** 分屏的点击处理挂在 `TerminalView`（外层 `Gtk.Box`）上，
靠事件从 VTE 冒泡上来触发。但 VTE 需要用左键做文本选择、拖拽和「把光标移到点击处」，
所以左键事件被 VTE 消费，不会冒泡——左键看起来毫无反应。右键能切换，只是因为 VTE
不占用右键，事件冒泡到了外层，加上那里显式调用了 `grab_focus()`。

这是设计失误：不该依赖事件冒泡来接收 VTE 已占用的按键。

**右键没有菜单。** 终端区域右键目前什么都不做，缺少复制、粘贴、分屏等常用操作。

## 2. 方案

**左键**：把点击处理直接挂到 VTE 控件上，用 `connect`（在 VTE 自身处理之前运行）而不是
`connect_after`。处理器只做一件事：切换焦点，然后返回 `False` 让 VTE 继续它原本的选择
行为。这样左键既能切换分屏，又不会破坏终端里的文本选择和光标定位。

**右键**：在 VTE 上拦下右键（返回 `True` 阻止 VTE 处理），弹出上下文菜单。
菜单项复用窗口已有的动作（`copy`/`paste`/`split-*`/`close-pane` 等），保证快捷键、
命令面板和菜单三处行为一致，不重复实现。

菜单内容：

| 分组 | 项目 |
| --- | --- |
| 剪贴板 | 复制选区、粘贴、粘贴为转义文本 |
| 分屏 | 左右分屏、上下分屏、关闭当前分屏、最大化当前分屏 |
| 终端 | 全选、清屏、重置终端 |
| 文件 | 在文件管理器中显示当前目录 |

「复制选区」在没有选区时置灰；「关闭分屏」在只剩一个分屏时改名为「关闭标签页」。
每项显示对应快捷键，方便用户从菜单学到键盘操作。

## 3. 关键设计

- **不重复实现动作**：菜单项调用 `window.activate_action("copy")` 等既有 GAction，
  单一实现来源，避免菜单和快捷键行为漂移。
- **右键定位**：用 `popup_at_pointer()`，在 Wayland/X11 下都能出现在指针位置。
- **左键不吞事件**：处理器返回 `False`，VTE 的选择与光标定位完全不受影响。
- **菜单可测试**：菜单构造抽成纯函数返回「项目列表」，不依赖弹出，测试可以直接断言
  分组、标签、快捷键提示与置灰条件。

## 4. 测试与验收

- `tests/test_terminal_menu.py`：菜单项分组与顺序、无选区时「复制」置灰、单分屏时
  「关闭分屏」文案变化、每项都带有快捷键提示、动作名都能在窗口动作表里找到。
- `tools/ui_smoke.py`：左键点击另一个分屏后焦点与高亮边框都转移；右键弹出菜单且
  至少包含复制/粘贴/分屏/关闭分屏；菜单触发的动作与快捷键一致。

## 5. 明确不做（YAGNI）

- 菜单里的「新建标签页」「退出」等窗口级操作（标题栏和快捷键已覆盖）
- 可自定义菜单项、图标菜单项、子菜单
